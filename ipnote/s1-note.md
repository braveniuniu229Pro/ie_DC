# S1-OSPF basic concept
## 路由协议
> 路由协议定义
>> “路由协议的存在，只为了一个目的，叫做传递或者生成路由条目。” 这个条目生成在三层网络设备上，其最终作用是指导设备在进行IP通信转发时，决定数据包该如何转发。

### 三层设备
> 定义：工作在OSI模型第三层（网络层）的设备，能够根据IP地址进行数据包的中转和转发。
> 常见设备：路由器、三层交换机、三层防火墙、无线控制器（AC）。

### 路由条目 (Routing Entry)

> 一个完整的路由条目通常包含三个最关键的信息：

>> 1. 目标网段与掩码：告诉路由器“我要去哪个网络” (如 192.168.1.0/24)。
>> 2. 出接口 (Outbound Interface)：数据包应该从路由器的哪个物理或逻辑接口发出去。
>> 3. 下一跳地址 (Next Hop)：数据包到达下一个路由器的IP地址是什么。

*补充：二层设备理论上每个接口并没有mac地址（实际上每个交换机可能会有，例如一个管理接口，计算brigeID等使用），他只是一个进行转发的透明设备，源mac和目的mac是链接的两个三层及以上设备的mac地址，源ip和目的ip是不会变的，但是源mac和目的mac是一直会随着转发的过程改变的，而交换机就是通过收到这些包以及使用arp协议收到目标的回包（本质也是收包）来学习mac到转发口之间的映射关系，然后根据目的mac地址直接到对应出口进行转发。* **所以实际上二层设备的mac地址只是一个字典的键，而出口是对应的值，得到对应设备的mac地址及学习对应映射关系的过程是同步的过程**

**基于以上补充的二层设备的相关转发原理，因此下一跳的ip地址是必须的，否则假设当前下一跳并非目的ip地址，中间连着若干交换机，交换机并不知道目的ip地址的mac，因为与目标ip的设备是不直接相连的，且由于交换机的arp协议只在二层的广播域进行转发，进而通过使用arp协议也无法获得对应需要转发的mac地址（就是获得对应的转发出口），因此无法得知转发到哪个出口**
