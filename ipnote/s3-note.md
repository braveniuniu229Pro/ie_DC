# 有关于双点双向引入问题防环路由机制的一些思考总结

**首先明确一件事，路由引入引入的是啥，在全局的ip路由表中有分不同协议安装的路由条目，我在一个协议中引入另一个协议的路由就是基于这个整体的ip路由表中去遍历这个被引入协议的路由条目且为active的路由然后引入，引入的是一个路由协议，这在ospf及lsa中有不同的表现形式，在ospf中更为复杂。
**

## 对于ospf
1. ospf对于一个路由的计算逻辑是这样的，首先搞清楚顺序，是先产生lsa，各种类型的lsa，然后每个路由器依据自身的lsdb利用spf算法去计算路由到ospf路由表，然后再依旧优先级看是否在全局ip路由表被使用，这里有个字段active进行区分是否被使用，全部的都会进去，没被使用就是inactive。
> 本机产生的 Type 5 LSA 不会参与本机的 ASE 路由计算，这可以避免直接根据自己发布的外部 LSA 形成 ASE 路由。但它不能解决双点双向引入中的所有路由反馈问题。其他 ASBR 发布的 Type 5 仍可能被本机计算，最终是否会被重新引入其他协议，取决于该 OSPF 路由是否成为本机全局 IP 路由表中的 Active 路由，以及是否通过路由策略。
2. 对于外部引入的一条路由，例如从isis引入的一个路由，它到ospf中是一个type 5 lsa，他会存在于这个路由器自身的lsdb中但是路由器会发现这个adv rtr就是自己，所以不会用这条type5 lsa去计算产生一个路由，因此作为引入的单位，它天然就不可能被再引入回isis协议，就是自己引入的不会立刻被引入回去，但是对于双点问题，另一个router引入产生的type5 lsa则会被计算成本router的路由，但正常情况下因为是ase类型的优先级很低，所以还有一个inactive这个条件去阻止他被isis引入回去，但是如果出现意外比如这个外部路由的优先级高于了引入区域的路由那么就会产生被引回去的可能。
3. 所以对于ospf来讲，无论是什么类型的lsa，其顺序都是先基于自身的各类lsa，type1-3去算AS内的，type 4，5去算外部的，其顺序都是先有lsa再产生路由。在引入的时候，可能会由于引入的单位本身就是一个路由条目了，以为顺序会发生变化，但实际上还是以先产生对应的type5 lsa这个形式来引入的，然后每台路由器去遍历全部的lsa来计算自己的ospf这个协议的路由。
4. 再来说一下filter-policy import和export这两个命令，这经常会让你产生困惑。
- 具体的行为就是import阻止的是已经计算出来的路由进入本机的路由表，但是对于其他路由器来讲因为所有的路由都是基于lsdb计算的，这条命令只是阻止由执行这条命令的router的ospf进程的路由表到ip路由表的这个过程，所以其本质是不会影响任何lsa的产生的，所以其他路由器依旧可以计算出这个被过滤的路由，不会有过滤的效果。但是依据上面的规则，由于不进入ip路由表，那么根本就不存在active的可能，所以当引入ospf协议的路由到其他协议的时候就不会被其他协议引入。
- export则作用在外部路由在引入的时候产生type 5 lsa的这个过程，如果执行了这个命令，那么在引入的过程中这条候选的路由如果被匹配就不会产生五类lsa，那么也就不会有后续传播的可能，更不可能被其他路由器计算出来了。

> 双点双向引入的路由防环机制
1. 路由引入的本质

路由引入不是直接复制源协议的全部 LSDB 或内部计算结果，而是从本机全局 IP 路由表中选择属于指定源协议、处于 Active 状态且符合其他引入条件的路由，再通过 import-route 引入目标协议。

2. OSPF 的 LSA 和路由计算
- 接收 LSA：LSA 进入 LSDB，再根据 OSPF 算法计算路由。
- 内部路由：Type 1/2 描述区域内拓扑，Type 3 描述区域间网络，Type 4 描述到 ASBR 的可达性。
- 外部路由：Type 5 描述外部目的网络，接收者据此计算 ASE 路由。
- ASBR 引入外部路由：先有源协议 Active 路由，经过 import-route 后产生 Type 5 LSA。
3. 本机产生的 Type 5

OSPF 会检查 Type 5 LSA 的 Advertising Router。如果是本机产生的 LSA，本机不会再根据它计算自己的 ASE 路由。这可以避免本机根据自己发布的 LSA 形成直接反馈，但不能保证跨协议双向引入绝对无环。

4. 双点双向引入的 Active 防环机制

假设两个 ASBR 都进行 IS-IS 与 OSPF 双向引入：
- 原始 IS-IS 路由通常优先于 OSPF ASE 路由。
- OSPF ASE 路由可能在全局 IP 路由表中处于 Inactive。
- import-route ospf 不会将该 Inactive 路由作为正常的重分发候选。
- 如果原始 IS-IS 路由消失，OSPF 路由可能变为 Active，进而重新被引入 IS-IS，产生路由反馈。
因此 Active 只是基于当前路由优选结果的辅助防环机制，不能代替 Route-Tag 和路由重分发历史检测。

5. filter-policy 的作用
- filter-policy import：过滤 OSPF 计算结果进入本机 RIB，不影响 LSDB 和 LSA 泛洪，但会间接影响本机其他协议能否通过 import-route ospf 引入该路由。
- filter-policy export：过滤 ASBR 通过 import-route 引入的外部路由，控制是否产生相应的 Type 5 LSA。
- area filter import/export：针对 ABR 接收或发布 Type 3 LSA。
6. 更可靠的防环机制

通过 Route-Tag 标记路由来源，并在反向引入时拒绝对应 Tag；对于支持的华为设备，还可以使用 Redistribute ID 和路由重分发历史检测机制。
