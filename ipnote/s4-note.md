# 关于stp协议算法流程的个人思考总结
关于STP协议一个主要的原则就是将准备发送的和从对端收到的进行对比，留下更好的，判断的依据首先是brige id 然后是rpc，再是发送的交换机id，以及发送的端口。而一个端口能够计算出要发送的bpdu，首先需要有一个基准，首先要知道自己是不是根桥，如果是那么直接全是dp，因为不会有更好的，如果不是根桥，那么第一步首先要在全部端口中找到一个最好的，这样的目的是找到一个以现在认知情况下到根桥的cost最小的。
> 对于每一个端口收到的都是另一个路由器发送的，或是自己的rp计算出来的，那么这里的cost计算就涵盖了对方的或自己的rp cost，只有在计算发送的时候才会加上自身端口的cost，因为只有rp才会计算自身要发送的bpdu，所以在选rp的时候就会比较加上cost的各个端口的bpdu谁更优，这个自身的计算是基于自身选出的rp得到的。对于一个要发送的bpdu的cost他永远代表的是我这个路由器在发送法向到根的最短距离。

按照目前的理解，步骤可以总结如下：
1. 首先在没收到任何bpdu的时候，自身初始都会产生以自己为根的bpdu，无疑是最好的，当自己为根时，不涉及rp选举，所有口都是dp。
2. 收到其他的bpdu以后，如果比自己保存的要好，那么就会产生变化，都会使得直接和其他口的bpdu进行对比，这里涉及两种情况：
   1. 对端发来的bpdu使得对根桥的认知产生了变化，那么这时尤其是不再以自己为根的时候，就需要首先选取rp，首先还是先比较根桥，然后现在自身保存的bpdu加上自身接口cost以后选取最优者为rp，这样做的目的也和rp的定义相吻合，即自身到根桥方向的最小代价，所以这里需要加上自身接口的代价，因为可以理解为相对于根桥永远是出方向。
   2. 对根桥的认知无变化，或是已经选取好rp后，那么现在就是在其他接口确认是dp还是ap，这个很简单，那么就是去对比现在收到的和基于现在自身rp计算出的准备发送的哪个更优，这样做的目的是针对一个链路的两端比如b，c，来对比他们那一端到达根的代价更小，同样的你准备发送的或是从对方收到的就是基于交换机自身的rp计算出来的到根的最小代价，所以收到的好那么这端就是ap，自己算出来的好，这里就是dp。
## 关于rstp优化的一些个人思考：
在rstp中在rp链路断开后，ap可以瞬间变为rp开启，为什么这样选出来的就是最好的哪个，即ap为什么是剩下的那个最好的。这里有点反直觉，就是ap不应该是每个链路里差的，而其他的dp端口是好的，为啥ap反而在这里成为了最好的变成rp的那个。这是因为计算考虑的方向不一样了。在计算rp的时候我们希望的是到根的代价最低的那个，现在之前的rp没了，我只能依靠剩下端口链接的其他交换机到根了，所以其实我需要的是从对方那里收到的即对方到根的代价加上我自己接口的代价最低的那个，先不考虑自身接口就是想得到对方到根的代价最低的那个，那么显然这个是ap对端的邻居，因为在此前这三个口在进行apdp选举的时候，都是基于rp计算的相同rpc的去对比的，而成为dp说明对面开肯定比自己烂，而只有ap对端的比自己好，那么ap对应的无疑是最好的。但这里也有一点小的个人疑惑，实际计算rp的时候应该选的是自身到根的代价最低那个，那么应该要考虑到自身这个口的cost，但是这样选出来的显然没有考虑这个因素，假设原来为ap的这个口cost非常高，那么即使他的邻居rpc是最低的，也可能导致他们加起来的和不是最低的，即这样直接用ap代替原来的rp可能未必是最优的rp。
